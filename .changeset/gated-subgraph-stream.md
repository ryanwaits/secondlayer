Subgraph client golden path. Typed `subscribe()` reads `/v1` like `rows`, keyless on loopback, and is a fetch-based SSE reader that carries the client's bearer token once the API is bound past loopback, so it streams rows on a token-gated instance instead of failing with 401. It tracks the wire-shaped `_block_height` of each delivered row and reconnects from it after a dropped or cleanly closed connection (with the same 1s pause either way), so rows at that height can be delivered twice. Every caller-supplied path segment (subgraph name, table, operation id, subscription id, outbox id) is percent-encoded before it reaches the URL. `typed()` threads the table's declared columns into filters and `orderBy`: `_id` / `_blockHeight` / `_txId` / `_createdAt` are the canonical system names, and the unprefixed `id` / `blockHeight` / `txId` / `createdAt` shorthands mean the system column only when your table declares no column of that name (a declared `id` column is always your `id`). `createStreamsClient()` resolves `apiKey` the same way as every other client (explicit option, then `INSTANCE_TOKEN`, then `SL_API_KEY`) and accepts `origin`, sent as `x-sl-origin` on every request and stream. `new SecondLayer({ origin, verify, verifyDumpsManifest })` reaches `sl.streams`, and the credential resolves once per client. README and AGENTS.md state the auth rule once: `/v1` reads are open on loopback, `/api` needs the token once one is configured.
