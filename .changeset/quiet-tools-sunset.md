`/tools` and `/tools/btc` are deprecated in favour of `@secondlayer/mcp`; they still import until the next major but get no new tools. `ai` and `zod` move from dependencies to optional peer dependencies, so a project that only reads contracts installs neither and a project that imports either tools entry installs both itself. The tools themselves are patched while they last: `readContract` and `getTransaction` return Clarity results through `cvToJSON` (uint/int as decimal strings) instead of crashing on a bigint; every principal, contract id, function name, txid and block hash input is validated before a request is built, and the actions percent-encode path segments (`getBalance`, `getAccountInfo`, `getBlock`, `getAccountHistory`, `readContract`, the extended tx source), so a model-supplied value cannot steer a request to another route; `estimateFee` reports `source: "min"` with the relay minimum when the node has no estimate instead of zeros, fills missing tiers from the nearest lower one and reports `tiers` (how many the node returned); `getBlock` with no arguments returns one block object instead of the list envelope (SDK action too); `estimateFee` decodes hex without Node `Buffer`; the bare exports are the factory bound to the default client, which now also reads `STACKS_NETWORK`, `STACKS_NODE_RPC_URL` and `SL_API_URL`. Every `BaseError` carries a stable string `code` (`HTTP_REQUEST_ERROR`, `TIMEOUT_ERROR`, ...) derived from its `name` field, so it survives minified class names, and it also appears in `toJSON()`.

BREAKING: `ContractCallError` and `ReadOnlyCallError` are removed (nothing ever threw them). `JsonRpcError.code` (the wallet's numeric JSON-RPC code) is renamed `rpcCode`; `code` is now the string `JSON_RPC_ERROR`. `cvToJSON` normalizes a buffer value that already carries `0x` instead of double-prefixing it.
