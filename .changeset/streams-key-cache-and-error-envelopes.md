Streams verification, error envelopes, and `context()` say what actually happened. The signing key is cached only after a successful fetch: a 5xx or dropped socket on `/public/streams/signing-key` now surfaces as a retryable `StreamsServerError` (`SIGNING_KEY_UNAVAILABLE`) and the next read fetches again, where it used to poison the client for its lifetime. SSE frames name their `key_id`, so a rotation mid-stream refreshes the key once instead of failing every frame. `verify: true` over plain http to a non-loopback host now throws up front and asks for `verify: { publicKey }`, since a key fetched over that path proves nothing; the tradeoff is one PEM to copy and a fail-closed rotation. Every failure status keeps the server's `{error, code}` envelope on `message`/`code`/`body`, Streams and Index alike (a Streams 400 keeps `code: "CURSOR_INVALID"`; a 401 keeps `TOKEN_REVOKED`; a 503 keeps its reason and `retryAfterSeconds`). `AuthError`, `RateLimitError`, `ValidationError`, and `StreamsServerError` accept `body` and `code` as trailing constructor arguments. **Breaking:** `VersionConflictError` is removed; nothing threw it and the API has no version-conflict code. The real 409 is `ApiError` with `code: "OPERATION_IN_PROGRESS"` on `subgraphs.deploy`/`reindex`/`backfill`. **Breaking:** `context()` fields are now `{ value, error? }` (`ContextField`), so a `null` says whether the API was unreachable, the token was rejected, or the read found nothing. `dumps.download()` hashes the body as it streams and retries a dropped socket or 5xx like a page fetch; it still returns the bytes. Empty-poll sleeps in `consume()` no longer leak an abort listener per poll onto the caller's signal. The `Retry-After` clamp is documented as a sleep cap (five minutes per attempt), which is what it always did. `kyselySink` and `drizzleSink` check the height column in `current_schema()` only, so a same-named table in another schema cannot pass the rollback guard.
