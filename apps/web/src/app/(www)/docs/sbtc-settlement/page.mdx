# sBTC settlement

Accepted isn't received. A `withdrawal-accept` event only means the signers *committed* to a Bitcoin sweep; Secondlayer verifies that `sweep_txid` against its own Bitcoin node and surfaces the result on the decoded sBTC feed.

Deposits need no such check — `completed-deposit` fires only after the signers see the BTC confirmations.

## Settlement on a withdrawal

Every peg-out lifecycle carries a `settlement` object. `GET /v1/index/sbtc/withdrawals/:request_id`:

```json
{
  "request_id": 42,
  "status": "ACCEPTED",
  "settlement": {
    "sweep_txid": "abcd…",
    "btc_confirmations": 7,
    "settlement_confirmed": true,
    "btc_block_height": 880321,
    "confirmed_at": "2026-06-01T00:00:00.000Z"
  }
}
```

`settlement_confirmed` is `true` past the confirmation threshold, `false` while the sweep is still shallow, `null` when there's no settlement record yet (no sweep observed — not a denial).

## Filtering the list

`GET /v1/index/sbtc/withdrawals` carries `settlement_confirmed` per row and as a filter:

```bash
# only peg-outs whose BTC sweep is confirmed
curl "https://api.secondlayer.tools/v1/index/sbtc/withdrawals?settlement_confirmed=true"

# the complete "not done" bucket — not yet confirmed, or no sweep yet
curl "https://api.secondlayer.tools/v1/index/sbtc/withdrawals?settlement_confirmed=false"
```

## The webhook

Subscribe to `sbtc_withdrawal_swept_confirmed` and skip the polling.

```ts
import { trigger } from "@secondlayer/sdk";

await client.subscriptions.create({
  url: "https://your-app.com/webhooks/sbtc-settlement",
  triggers: [trigger.sbtcWithdrawalSweptConfirmed()],
});
```

- Scope with `requestId` / `sweepTxid`.
- Fires **once** per sweep, when `btc_confirmations` first crosses the threshold (default 6).
- **Forward-only** — settlements confirmed after you subscribe, never a backfill.
- A Bitcoin reorg that un-confirms a sweep never re-fires it; the read self-corrects.

Delivery is the standard `chain.{type}.apply` envelope; `event` carries the settlement specifics:

```json
{
  "action": "apply",
  "trigger": "sbtc_withdrawal_swept_confirmed",
  "event": {
    "topic": "withdrawal-swept-confirmed",
    "request_id": 42,
    "sweep_txid": "abcd…",
    "btc_confirmations": 6,
    "btc_block_height": 880321,
    "confirmed_at": "2026-06-01T00:00:00.000Z",
    "amount": "100000",
    "sender": "SP…"
  }
}
```

See [Subscriptions](/docs/subscriptions) for delivery formats, signature verification, and the full trigger list.

<Callout type="info" title="What this proves — and what it doesn't">

Settlement is verified against our own Bitcoin node, not a custody guarantee — a signer set still controls the pegged UTXO.

</Callout>
