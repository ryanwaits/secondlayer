Decoded Stacks chain data, backfilled from genesis, reorg-safe and kept current. Trust, and [verify it yourself](/docs/verification).

## Where do you start?

<Fork question="Do you already have an API layer?" name="api-layer">
<ForkPath value="index" label="Yes, I run one">

```ts index.ts
import { Index } from "@secondlayer/sdk";

await new Index().events.consume({
  eventType: "ft_transfer",
  fromCursor: await db.loadCheckpoint(),
  // !ref(1:4) fork-index-batch
  onBatch: async (events, envelope, ctx) => {
    await db.commit(events, ctx.cursor);
    return ctx.cursor;
  },
  // !ref fork-index-reorg
  onReorg: (reorg) => db.deleteFromHeight(reorg.fork_point_height),
});
```

[Write rows and the cursor in one transaction](focus:fork-index-batch), and [roll back to the last good block](focus:fork-index-reorg) when a reorg lands. You keep your schema and serve it however you already do. [Index →](/docs/index)

</ForkPath>
<ForkPath value="subgraphs" label="No">

```ts subgraph.config.ts
import { defineSubgraph } from "@secondlayer/subgraphs";

export default defineSubgraph({
  name: "sbtc-flows",
  // !ref fork-sg-start
  startBlock: 8000000,
  sources: { transfers: { type: "ft_transfer", assetIdentifier: "SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-token::sbtc-token" } },
  schema: { transfers: { columns: { amount: { type: "uint" }, sender: { type: "principal" } } } },
  handlers: {
    // !ref fork-sg-handler
    transfers: (event, ctx) => ctx.insert("transfers", { amount: event.amount, sender: event.sender }),
  },
});
```

The [first deploy backfills from your start block](focus:fork-sg-start), and [one write per event](focus:fork-sg-handler) fills a table that REST serves. You get an API you didn't write. That's the point, and the tradeoff. [Subgraphs →](/docs/subgraphs)

</ForkPath>
<ForkPath value="streams" label="I decode it myself">

```ts indexer.ts
await sl.streams.events.consume({
  types: ["ft_transfer"],
  fromCursor: await db.loadCheckpoint(),
  onBatch: async (events, envelope, ctx) => {
    // !ref fork-st-batch
    await db.insertEvents(events, ctx.cursor);
    return ctx.cursor;
  },
  // !ref fork-st-reorg
  onReorg: (reorg) => db.deleteFromHeight(reorg.fork_point_height),
});
```

You get [raw, signed frames to decode](focus:fork-st-batch), and a [reorg rewinds to the fork point and re-delivers](focus:fork-st-reorg). This is what Index is built on. [Streams →](/docs/streams)

## Get started

Five commands from key to a row you can check against Bitcoin. Keys come from [/account/keys](/account/keys).

Using an agent? `bunx skills add ryanwaits/secondlayer --skill secondlayer -y`

<Steps>

### Install and set your key

Every command and example reads these two variables.

```bash
bun add -g @secondlayer/cli
export SECONDLAYER_API_URL=https://api.secondlayer.tools
export SECONDLAYER_API_KEY=sk-sl_...
```

### Create a subgraph

Scaffolds a typed subgraph from a contract's events.

```bash
secondlayer subgraphs create my-balances --from-contract SP....my-contract
```

### Deploy

Set a `startBlock` first: the event and transaction rows it reads bill. Reads of your own tables are free.

```bash
secondlayer subgraphs deploy subgraphs/my-balances.ts
```

### Query

```bash
curl -H "Authorization: Bearer $SECONDLAYER_API_KEY" \
  "$SECONDLAYER_API_URL/v1/subgraphs/my-balances/balances"
```

### Verify

Proves the block your rows came from against Bitcoin. [Verification →](/docs/verification)

```bash
secondlayer verify block 9137005
```

</Steps>

Prefer your own box? [Self-host](/docs/self-host) is the same product on your Postgres.
