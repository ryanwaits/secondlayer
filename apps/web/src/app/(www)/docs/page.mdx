# Your indexer, on our decoders

We run the chain indexer and the decoder. You write the loop, own the database, and deploy it wherever your code already runs.

## What are you building?

| You want | Use | What you write | Where it runs |
| --- | --- | --- | --- |
| Your app's own index | **Index** | A `consume()` loop: `onBatch` writes rows, `onReorg` rolls them back. `sl index codegen` emits the mirror schema so your tables can't drift. | Your process, your database — [deploy it](/docs/deploy) to Railway, Fly, or a box you own. |
| Your own tables with zero ops | **Subgraphs** | One TypeScript file — sources, schema, handlers. | We run the loop: hosted Postgres, public reads, backfill and reorgs included. |
| To build from the raw inputs | **Streams** | A consumer over the signed raw firehose: bulk dumps, replay, automatic reorg rewind. | Your process. This is what Index itself is built on. |
| An answer right now, no install | **Index** | Nothing — one keyless request returns decoded JSON with a resume cursor, the chain tip, and overlapping `reorgs[]`. | Your terminal. See the [API reference](/docs/api-reference). |
