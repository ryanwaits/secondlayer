# MCP and skills

Give Claude Code, Cursor, or any MCP client live access to Secondlayer, and teach it the rules for building on it.

## Connect

Point your agent at the hosted server and sign in once in the browser. In Claude Code:

```bash
claude mcp add --transport http secondlayer https://api.secondlayer.tools/mcp
```

The first call opens a sign-in page: check the app's name and allow it. Reads it makes use your credits, like reads made with a key. The hosted server carries the read tools only, so install the local server when you need to deploy subgraphs or manage webhooks.

### Remote

Any client that speaks Streamable HTTP takes the URL alone:

```json .mcp.json
{
  "mcpServers": {
    "secondlayer": {
      "type": "http",
      "url": "https://api.secondlayer.tools/mcp"
    }
  }
}
```

| Credential | When |
| --- | --- |
| Browser sign-in (OAuth) | The default. The client registers itself and opens the consent page. |
| `Authorization: Bearer <sk-sl_ key>` | A client without OAuth support. |

- An app can't make or revoke keys. Revoke an app under Apps on [/account](/account#keys).
- Tools marked "Local only" below are not on the hosted server.

### Local

The `@secondlayer/mcp` package runs the server over **stdio**, with every tool:

```json .mcp.json
{
  "mcpServers": {
    "secondlayer": {
      "command": "npx",
      "args": ["-y", "@secondlayer/mcp"],
      "env": {
        "SECONDLAYER_API_URL": "https://api.secondlayer.tools",
        "SECONDLAYER_API_KEY": "<sk-sl_ key from /account#keys>"
      }
    }
  }
}
```

A client's JSON `env` can't read your shell, so this block holds the hosted values from the [Introduction](/docs#get-started) literally.

On your box, set these instead of the key ([Self-host](/docs/self-host#use-these-docs-on-your-box)):

| Variable | Value |
| --- | --- |
| `SECONDLAYER_API_URL` | `http://127.0.0.1:3800` |
| `INSTANCE_TOKEN` | From `.env.local` |

The same package's `secondlayer-mcp-http` command serves it over HTTP behind your own URL, with sessions and an optional `SECONDLAYER_MCP_SECRET` bearer.

### Authentication

| Surface | Reads | Writes |
| --- | --- | --- |
| Index, Streams, Contracts, Scaffold | Hosted: `SECONDLAYER_API_KEY`. Self-host: open on loopback | — |
| Subgraphs, Webhooks | Hosted: `SECONDLAYER_API_KEY`. Self-host: open on loopback | Hosted: `SECONDLAYER_API_KEY`. Self-host: `INSTANCE_TOKEN` |

A token sent on a loopback read that did not need it is ignored, never rejected.

### Start here

Read `secondlayer://context` first, then any other resource you need, before calling tools.

<McpResources />

For Index, call `index_discover` first to learn every event type, its columns, and the filters it accepts.

### Tools

Reads are cursor-paginated. Writes that kick off work (reindex, backfill, replay, deploy) return an `operationId` to poll. Account tools register only when `SECONDLAYER_API_URL` is the hosted API.

<McpTools />

### Notes

- **One-time secrets.** `webhooks_create` returns its signing secret exactly once: forward it to the user.
- **Cursors are opaque** and per-keyspace: contract-call cursors are not interchangeable with event cursors.
- **Tail without streaming.** For subgraph tables, every page with rows returns `next_cursor`; poll with `cursor = next_cursor ?? cursor`.
- See the [REST API](/docs/rest-api) for the underlying endpoints.

## Agent skill

The `secondlayer` skill teaches an agent the rules for building on Secondlayer: read the print schema before writing a handler, prove a mapping writes rows before deploying it.

```bash
bunx skills add ryanwaits/secondlayer --skill secondlayer -y
```

| Use | When |
| --- | --- |
| The skill | An agent writes code against Secondlayer |
| MCP | It needs live state: your subgraphs, webhooks, chain tips |

The skill is static text that can't see your instance, and MCP can, so install both. Source: [`skills/secondlayer`](https://github.com/ryanwaits/secondlayer/tree/main/skills/secondlayer).
