# PoX-5 events

Index on the `pox-5` boot contract: decoded bond prints, and a webhook when a registration lands. Same loop as any other Index feed. Not a stacking product; positions and payouts are a [subgraph](/docs/subgraphs) you deploy.

## Read decoded bond prints

Protocol-bond registrations are prints on `pox-5`. Filter the Index feed by topic.

```bash
curl "$SECONDLAYER_API_URL/v1/index/pox5/events?topic=register-for-bond&limit=5" \
  -H "Authorization: Bearer $SECONDLAYER_API_KEY"
```

Each row has `bond_index`, `amount_sats`, `is_l1_lock`, and `data.btc-lockup` (L1 txids). This is the print log, not a position scoreboard. Envelope, cursors, `?confirmed=true`: [Index](/docs/index).

The SDK pages it for you and narrows the row to the columns you ask for:

```ts
for await (const e of sl.index.pox5.events.walk({ topic: "stake", signer: "SP…" })) {
  console.log(e.block_height, e.staker, e.amount_ustx);
}

const { events } = await sl.index.pox5.events.list({
  topic: "register-for-bond",
  fields: ["bond_index", "amount_sats"],
});
```

Filters: `topic`, `staker`, `signer`, `signerManager`, `bondIndex`, `rewardCycle`, `fromHeight`, `toHeight`, `confirmed`. `signer` covers a pool's claims and key grants too — the contract prints those under `signer-manager`, but it's the same principal, so `signer=` alone returns a pool's full activity. `signerManager` stays for compatibility.

## Consume the print log

`pox5.events.consume()` is the checkpointed sweep over the pox-5 print log: all 19 topics, or filtered to one:

```ts
await sl.index.pox5.events.consume({
  signer: "SP…", // server-side; omit for every signer
  fromCursor: await db.loadCheckpoint(),
  fromHeight: 0,
  onBatch: async (events, _envelope, ctx) => {
    for (const e of events) await db.upsertPox5Event(e); // typed columns, no payload parsing
    await db.saveCheckpoint(ctx.cursor);
    return ctx.cursor;
  },
  onReorg: async (r) => db.deleteFromHeight(r.fork_point_height),
});
```

## Get a webhook on registrations

A chain webhook POSTs matching prints to your URL.

```bash
secondlayer webhooks create pox5-bonds \
  --url https://example.com/webhook \
  --trigger '{"type":"print_event","contractId":"SP000000000000000000002Q6VF78.pox-5","topic":"register-for-bond"}'
```

Same shape for `bond-distribution` when payouts start. Trigger grammar and signatures: [Webhooks](/docs/webhooks). Bond-level tables (positions, allowlist, payouts) are a subgraph you deploy: [Subgraphs](/docs/subgraphs).
