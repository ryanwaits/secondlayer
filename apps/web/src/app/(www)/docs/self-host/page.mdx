# Self-host

The same product on your Postgres: one container, no cluster, no queue. Bring your own node, or bundle one.

## What you need

A box with Docker, 4 GB RAM, and the CLI (`bun add -g @secondlayer/cli`). Mainnet full history needs a 600 GB SSD; see [Hardware](/docs/self-host/hardware).

## Start it

```bash
secondlayer setup
```

One guided command: generates secrets, writes `docker-compose.yml` and `.env` into the current directory, brings the stack up, restores verified history from the archive, and verifies the result. With an external node, it prints the stanza to paste into your node's `Config.toml` ([details](/docs/self-host/production#connect-your-node)).

The API listens on `http://127.0.0.1:3800`. Check it is up:

```bash
curl http://127.0.0.1:3800/health
```

## Use these docs on your box

Every example in these docs reads `SECONDLAYER_API_URL` (and `SECONDLAYER_API_KEY` where a header is shown). On your box, point the URL at your own API.

```bash
export SECONDLAYER_API_URL=http://127.0.0.1:3800
```

Reads on a loopback bind need no key, and a header carrying an unknown or empty key is ignored there, so the same curl lines work unchanged. Writes over curl, and any read past loopback, send `Authorization: Bearer $INSTANCE_TOKEN`. The CLI, SDK and MCP send `INSTANCE_TOKEN` for you on any URL that is not the hosted API, so `secondlayer subgraphs deploy` needs only the token in your env (MCP needs it in the client config's `env`, not just your shell):

```bash
export INSTANCE_TOKEN=…            # from .env.local
secondlayer subgraphs deploy ./my-subgraph.ts
```

Leave `SECONDLAYER_API_KEY` for the hosted account: archive quote, fetch and credits read it as the account key, so setting it to the instance token breaks them. Keep `POSTGRES_PORT` and `INDEXER_PORT` on loopback.

## Stop it

From the directory `setup` wrote. The index, chainstate, and keys survive.

```bash
secondlayer uninstall            # dry run
secondlayer uninstall --apply
```
