# REST API

The shared envelope, cursor, and filter grammar across index, streams, and subgraph tables. Anonymous and unmetered unless noted; keys and tiers: [Authentication](/docs/authentication).

## Response envelope

```json
{
  "events": [{ "block_height": 8054704, "event_index": 12 }],
  "next_cursor": "8054704:12",
  "tip": { "block_height": 8054704, "finalized_height": 8054262 },
  "reorgs": []
}
```

```json
{
  "rows": [{ "_id": 48138, "block_height": 8054704 }],
  "next_cursor": "48137",
  "tip": { "block_height": 8054704, "subgraph_height": 8054704, "blocks_behind": 0 }
}
```

Cursor format is `<block_height>:<event_index>`. `tip.finalized_height` is the burn-confirmation finality boundary; rows at or below it never reorg, which is what a `finalizedOnly` consumer gates on.

## Pagination

| Surface | Page size | Ordering |
| --- | --- | --- |
| Subgraph tables | `_limit` (default 50, max 1000) | `_order=asc` / `_order=desc`; bare `limit` or `order` returns `400` |
| Index | `limit` (default 200, max 1000) | Fixed by the keyset cursor, no order param |
| Streams | `limit` (default 100, max 1000) | Fixed by the keyset cursor, no order param |

Pass the previous response's `next_cursor` back as `cursor` (index and `/v1/subgraphs`). Index also accepts `from_cursor` (exclusive-start alias, mutually exclusive with `cursor`) and `from_height`/`to_height`.

## Filtering

```bash
curl https://api.secondlayer.tools/v1/subgraphs/sbtc-flows/transfers \
  -G \
  -d "sender=SP3PE7Q9...X44J" \
  -d "_order=desc"
```

Subgraph tables filter on any column, validated against the table's schema. Index and streams take a fixed set per endpoint (`types`, `not_types`, `contract_id`, `sender`, `recipient`, `asset_identifier` on `/v1/streams/events`).

<Callout type="warning" title="Unknown params are rejected">

Any unrecognized query param returns `400`; the error suggests the closest valid param.

</Callout>

## /v1 subgraphs open reads

| Route | Returns |
| --- | --- |
| `GET /v1/subgraphs` | Public subgraphs, plus your own with a bearer |
| `GET /v1/subgraphs/:name` | Metadata: tables, columns, indexing tip |
| `GET /v1/subgraphs/:name/:table` | Rows; `/count`, `/aggregate`, `/:id`, `/stream` (SSE) alongside |

Public subgraphs read anonymously: wildcard CORS, no key. Private ones need the owner's `sk-sl_` bearer; anonymous requests get `404`, no existence leak.

`_id`-keyset pagination: `?cursor=<next_cursor>` resumes, `_order` sets direction; `_limit`, `_fields`, `_search`, and column filters work as everywhere else. `_offset` and `_sort` are **rejected with `400`** here — dashboard-only, on the authed `/api/subgraphs`.

Rate limits: anonymous 100 rps, keyed 50 rps; watch the `X-RateLimit-*` headers.

## Streaming (SSE)

```bash
curl -N -H "Authorization: Bearer $SL_API_KEY" \
  "https://api.secondlayer.tools/v1/streams/events/stream?types=ft_transfer"
```

Two endpoints push rows as Server-Sent Events (`Content-Type: text/event-stream`) over one long-lived connection, each with a `ping` keepalive every 20s.

- `GET /v1/streams/events/stream`: raw chain event firehose, bearer auth. Same filters as `/v1/streams/events`, plus a start position (`cursor`/`from_cursor`/`from_height`); with none it live-tails from the reorg-clamped tip.
- `GET /v1/subgraphs/:name/:table/stream`: new subgraph-table rows. Anon for public, `sk-sl_` bearer for private. Takes `?since=<block_height>` (replay from a height, then tail) plus the table's column filters.

Ergonomic clients: [Streams](/docs/streams#real-time-firehose-sse), [SDK](/docs/sdk#subscribe-to-the-live-stream-sse).

## Aggregates

`GET /v1/subgraphs/:name/:table/aggregate` runs scalar aggregates over the same filtered set as the list and count endpoints.

```bash
curl https://api.secondlayer.tools/v1/subgraphs/sbtc-flows/transfers/aggregate \
  -G \
  -d "status=active" \
  -d "_count=true" \
  -d "_sum=amount" \
  -d "_min=amount" \
  -d "_countDistinct=sender"
```

```json
{
  "count": 42,
  "countDistinct": { "sender": 7 },
  "sum": { "amount": "12300000000" },
  "min": { "amount": "1000000" }
}
```

| Param | Effect |
| --- | --- |
| `_count=true` | `COUNT(*)` |
| `_countDistinct=col1,col2` | Distinct count per column |
| `_sum=col`, `_min=col`, `_max=col` | Comma-separated; **numeric columns only** (`uint`/`int`, plus the system `_block_height`) |

`count` and `countDistinct.col` are JSON numbers; `sum`/`min`/`max` are **lossless strings**. Over an empty set `sum` is `"0"`, `min`/`max` are `null`. No aggregate param → `{ "count": <n> }`.

| Status / code | Cause |
| --- | --- |
| `400 NON_NUMERIC_COLUMN` | A non-numeric `_sum/_min/_max` column |
| `400 INVALID_COLUMN` | An unknown column |
| `400 TOO_MANY_AGGREGATES` | Past 32 aggregate columns per request |

Typed as `subgraph.<table>.aggregate(spec)` in the [SDK](/docs/sdk#aggregate-subgraph-rows).

## Print-event schemas

```bash
curl "https://api.secondlayer.tools/v1/index/contracts/SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-registry/print-schema"
```

`GET /v1/index/contracts/:contract_id/print-schema` returns per-topic print payload schemas inferred from indexed history; response shape in [Index](/docs/index#print-schemas).

- Cached `Cache-Control: public, max-age=300` with a weak `ETag`; send `If-None-Match` for `304`.
- Takes **no query params**; any param is rejected with `400 VALIDATION_ERROR`.

## Transaction-inclusion proof

```bash
curl "https://api.secondlayer.tools/v1/index/transactions/0x<tx_id>/proof"
```

`GET /v1/index/transactions/:tx_id/proof` returns a trustless inclusion proof. Response body, trust levels, error codes, and the `@secondlayer/sdk` verifier: [Verification](/docs/verification#errors).
