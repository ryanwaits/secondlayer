# Verified archive

Check your chain history against a signed canonical archive, repair what diverges, or restore a fresh instance from it.

## Check your data

```bash
secondlayer verify raw --against https://archive.secondlayer.tools/latest.json
```

Read-only. Digests stay on your machine. Default target is `raw`.

The archive is a best-effort public utility, not a hosted service. Verification is free and always will be.

<details id="which-command">
<summary>Which command</summary>

| Job | Command |
| --- | --- |
| Check raw identity columns | `secondlayer verify raw --against <latest.json>` |
| Check every published dataset | `secondlayer verify all --against <latest.json>` |
| Check one decoder | `secondlayer verify decode:ft_transfer --against <latest.json>` |
| Also check payload columns | `secondlayer verify --against <latest.json> --deep` |
| Plan a repair | `secondlayer repair --against <archive>` |
| Write the repair | `secondlayer repair --against <archive> --apply` |
| Restore a fresh instance | `secondlayer bootstrap --against <archive>` |
| Price a hosted fetch | `secondlayer archive quote --against <archive>` |
| Check from your instance's API | `POST /v1/archive/verify` |
| Read the archive tip | `secondlayer archive latest` |
| Read the node attestation | `GET attestations/<digest>/node.json` |
| Read operational status | `GET status.json` |

`<latest.json>` is the signed pointer. Start there.

`secondlayer verify`, `repair` and `bootstrap` are the same commands as `secondlayer archive verify`, `archive repair` and `archive bootstrap`. Pick either form; the examples here use the short one.

</details>

<details id="targets">
<summary>Targets</summary>

| Target | Checks |
| --- | --- |
| `raw` | `blocks`, `transactions`, `events` |
| `all` | Every dataset the manifest publishes |
| `decode:<name>` | That decoder's datasets |
| `subgraph:<name>` | That subgraph's datasets |

No matching dataset in the manifest is exit `2`.

</details>

<details id="reading-the-output">
<summary>Reading the output</summary>

Clean output exits `0`. Divergence names the ranges:

```
⚠ 1 of 175 ranges diverge from the archive.

RANGE              DATASET  STATUS        EXPECTED  LOCAL
-----------------  -------  ------------  --------  -----
8500000-8549999    blocks   data differs  50000     50000

These ranges hold different data than the signed archive.
```

Equal row counts with differing data means the same heights hold different blocks: a fork point left on the losing branch.

</details>

<details id="exit-codes">
<summary>Exit codes</summary>

| Code | Meaning |
| --- | --- |
| `0` | Local data matches the archive. |
| `1` | Divergence found; every divergent range is listed. |
| `2` | Unanchored: the archive was unreachable or its signature failed. |

`2` is never success. Not being able to check differs from being fine.

</details>

<details id="flags">
<summary>Flags</summary>

| Flag | Effect |
| --- | --- |
| `--against <manifest>` | Archive `latest.json`, a snapshot manifest URL, or a local path. Required. |
| `--quick` | Identity columns only. Default. |
| `--deep` | Also recompute semantic digests (`raw_tx`, event `data`, `function_args`). |
| `--anchor` | Require a verified archive signature. |
| `--from-block <n>` / `--to-block <n>` | Limit the checked range. |
| `--counts` | Also compare transaction and event row counts. Slower. |
| `--semantic` | Alias of `--deep`. |
| `--public-key <pem>` | Pin a signing key. Default is the archive key built into the CLI release, or `ARCHIVE_SIGNING_PUBLIC_KEY` when set. |
| `--insecure` | Compare without verifying the signature. Result is unverified. |
| `--json` | Machine-readable report on stdout. |

</details>

<details id="from-your-instances-api">
<summary>From your instance's API</summary>

`POST /v1/archive/verify` runs the same raw-identity check on the instance itself, read-only, with the archive URL in the body. It answers `clean`, `diverged` or `unanchored`, and a failed signature is a `200 unanchored`, never `clean`. Body fields and responses: [API reference](/docs/api/instance#verify-archive).

```ts
const result = await sl.archive.verify({
  against: "https://archive.secondlayer.tools/latest.json",
  fromBlock: 0,
  toBlock: 99999,
});
```

The tradeoff against the CLI: identity digests only. `--deep` is CLI-only.

</details>

<details id="repair-what-diverges">
<summary>Repair what diverges</summary>

```bash
secondlayer repair --against <archive>            # plan
secondlayer repair --against <archive> --apply    # write it
```

Dry-run by default. The plan names exact heights, not ranges:

```
HEIGHT   ACTION   LOCAL         ARCHIVE
-------  -------  ------------  -------
8501111  replace  0xd4deb46c6d  0xedb6ba8322
```

Each partition is hashed against the signed digest before any row is read. One transaction per partition, so an interrupted repair leaves no half-corrected range.

<Callout type="warning" title="Heights the archive doesn't have">

Local heights absent from the archive are reported, never deleted, because transactions and events reference them.

</Callout>

Decoded rows are not rebuilt. Re-run your decoders for repaired ranges.

</details>

<details id="restore-a-fresh-instance">
<summary>Restore a fresh instance</summary>

```bash
secondlayer bootstrap --against <archive>
```

Shows both timings before it starts, then restores and verifies itself:

```
coverage   genesis → 8,745,422
signature  verified

  sync from genesis    ~19.4 days (estimate)
  restore from archive ~2.3 hours
```

Refuses a database that already holds blocks; use `secondlayer repair` for an existing instance. `--to-block <n>` stops early; `-y` skips the prompt.

`--from-block <n>` restores forward-only: whole partitions starting at or after `n`, with everything below declared out of scope rather than missing, so `verify` doesn't read it as divergence. The tradeoff: the disk floor at boot is still the full-history one.

</details>

<details id="credits">
<summary>Credits</summary>

Bootstrap, backfill, and reindex fetch from the archive metered per partition bundle, quoted against your balance before anything is charged; verification is free. `secondlayer archive quote --against <archive>` prices a fetch without charging; `--from-block`/`--to-block` narrow it, `--flow repair` prices a repair, and it exits `2` when your balance falls short. Buy with `secondlayer credits buy`; packs, balance, and how the quote/confirm flow works: [archive credits](/docs/authentication#archive-credits).

</details>

<details id="what-the-archive-is">
<summary>What the archive is</summary>

Immutable, digest-addressed Parquet partitions on R2, published from a repeatable-read snapshot of a production Stacks index. Three datasets (blocks, transactions, events), partitioned by height.

| Object | Contents |
| --- | --- |
| `latest.json` | Signed pointer at the current snapshot. Start here. |
| `snapshots/<digest>.json` | Signed manifest: coverage, counts, per-object digests, finality rule, audit. |
| `blocks/`, `transactions/`, `events/` | Range-partitioned Parquet, digest in the filename. |
| `digests/<range>-<sha16>.parquet` | Per-height sidecar: one row per height with the block digest and rolled-up transaction and event digests. |
| `attestations/<digest>/node.json` | Signed independent node audit. `coverage` is the attested window; `stats` is exact; `mismatches[]` is a capped sample. |
| `status.json` | Short-cache operational state: `fresh`, `lagging`, `stale`, `gap`, `failed-audit`, `source-unavailable`. `source.decoder_head` is the running Index decoder; `archive.coverage_to_block` is the last signed publish. |
| `reports/incidents/` | Signed incident reports, newest first via `index.json`. |

Publishing is append-only. Each partition carries a SHA-256 over its bytes and a semantic-v1 digest over its canonical encoding. The manifest is ed25519-signed.

</details>

<details id="assurance-levels">
<summary>Assurance levels</summary>

The manifest states an assurance level per range: `db-reconstructive`, `node-attested`, or `observer-attested`. What each means: [Verify](/docs/verification#archive-assurance-levels).

</details>
